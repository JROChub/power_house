MFENX LOCAL V1 / RELEASE EVIDENCE

Software-defined local supercomputer

MFENX is a software-defined local supercomputer. Its Local v1 profile compiles exact work into MFENX ISA 6, assigns durable pieces to deterministic CPU lanes, stores tensors by content, recovers from checkpoints, and independently replays every output before publishing it.

The Linux executable performs the physical work on the host's CPU cores and local storage. It is not a browser simulation and does not send execution to a VPS or cloud worker. This profile requires no GPU device, GPU driver, or network.

01 / SYSTEM DEFINITION

What this supercomputer is

a compute architecture implemented in software and executed by local CPU cores and storage
SYSTEM TYPE

Software-defined local supercomputer

MFENX defines an instruction set, compiler, scheduler, storage format, memory certificate, recovery protocol, and verifier as one system. Local v1 is the profile that maps this architecture onto the host's CPU and storage.

PHYSICAL EXECUTION

Deterministic parallel CPU lanes

The compiler binds a lane count and piece schedule into the machine image. Piece p belongs to lane p mod lanes. The acceptance harness observes distinct named operating-system tasks overlapping while they execute useful work.

MEMORY MODEL

Durable data is separate from managed RAM

Complete tensors remain in a content-addressed store. CPU lanes load bounded authenticated chunks and tiles. Each completed output piece is synchronized with a receipt, so a killed process can reuse valid pieces and compute only those still missing.

LOCAL V1 SCOPE

Exact streamed i32 matrix multiplication

This release certifies one manifest-backed rank-two operation with defined wrapping arithmetic. "Software-defined supercomputer" does not mean custom MFENX silicon, independent compute nodes, or a TOP500 performance ranking.

03 / EXECUTION PATH

How an execution works

each stage is validated and the result is withheld until exact replay passes
01 IMPORT / CREATE split canonical matrix bytes into BLAKE3-addressed chunks
02 COMPILE validate shapes and emit a digest-bound ISA-6 image, lane schedule, and memory certificate
03 EXECUTE physically execute bounded tiles on CPU lane p mod lanes with exact wrapping-i32 arithmetic
04 CHECKPOINT synchronize each output piece and its content-bound receipt before reuse
05 VERIFY / PUBLISH replay every output independently; publish only when all values match
Browser scope

The browser hashes selected acceptance files and, on request, the Linux executable. It does not execute or simulate the workload. Process memory and simultaneous CPU-lane tasks were recorded outside the product through Linux /proc by the acceptance harness.

Scope. MFENX is called a software-defined local supercomputer because its ISA, compiler, deterministic parallel scheduler, content-addressed storage, crash recovery, and independent verifier operate as one compute architecture. Local v1 runs that architecture on physical CPU cores and local storage. The claim is architectural; it is not a claim of custom silicon, distributed nodes, benchmark speed, or TOP500 classification.

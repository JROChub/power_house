    VERIFICATION COMPONENTS

    Candidate generation and checking are separate.

    01

    CANDIDATE MODEL

    The candidate may come from ONNX Runtime, TensorRT, Olive, another compiler, or a manual transformation.

    →
    02

    PYTHON GATE

    Snapshots bytes, enforces batch one Float32 semantics, executes every declared row, and retains raw output bits and paired timings.

    →
    03

    RUST ADJUDICATOR

    Separately parses evidence, reads bound labels, rehashes artifacts, and recomputes metrics, claims, and the release verdict.

    →
    04

    NUMPY SHADOW CHECK

    A distinct strict ONNX evaluator uses neither Gate nor ONNX Runtime. Unsupported device and latency claims remain inconclusive.
